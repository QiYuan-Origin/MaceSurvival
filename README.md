# MaceSurvival · 重锤大逃杀

面向 **Minecraft Java Edition 1.21.11、Paper、Java 21** 的单端生存竞技插件。玩家从高空选择落点，搜集星级补给，使用重锤、风弹与长矛交战，在收缩的战场中争取最后的胜利。

插件按独立玩法服设计：入服进入等待大厅，比赛中途加入则进入旁观；大厅快捷栏、比赛背包、地图生成与局间清理由插件管理。地图由插件生成，无需管理员提前制作竞技场，也不需要材质包。

## 游玩方式

当前只有一套大逃杀规则，支持以下参赛方式：

- **单人生存**：不加入小队即可参与，每位单人玩家各自构成一个阵营。
- **自由组队**：在等待阶段创建或加入公开小队，默认每队最多四人；也可以由队长通过命令邀请玩家。

单人与不同人数的小队在同一场对局中竞争。队伍调整在等待和倒计时阶段开放，进入比赛后锁定；默认禁止队友伤害。`squad.size` 可设置为 1～16，默认四人。设置 `squad.allow-solo: false` 后，只有已加入小队的玩家符合参赛条件；菜单会提示组队要求，等待提示按真正符合资格的玩家和阵营计算，离队后需重新组队才可参赛。

一局比赛的流程：

1. **等待大厅**：右键指南针打开玩法菜单，查看战绩、组队或调整快捷栏布局。
2. **倒计时**：默认至少两名符合条件的玩家、至少两个不同阵营才能开局；默认倒计时 45 秒。人数或阵营不足时暂停倒计时。
3. **战场准备与降落**：生成本局地形、建筑和补给，短暂黑屏后进入高空降落。转动水平视角控制落点，接近地面自动缓降。
4. **搜索与交战**：落地后即可收集补给和搭建方块。全部存活参赛者完成降落后开始计时，默认有 20 秒保护期；保护期结束后开放交战。
5. **边界收缩**：默认比赛开始 300 秒后收缩，持续 600 秒，最终边界直径 24 格。
6. **胜负结算**：最后一个存活阵营获胜。单人生存结算给幸存玩家，小队胜利计入本局该队参赛成员的战绩；达到默认 1800 秒时限则按平局结束。
7. **下一局**：默认结算画面持续 10 秒，然后返回大厅并清理本局竞技场，继续等待下一局。插件不会执行服务器关闭或自动重启。

死亡后进入旁观。比赛中退出视为淘汰并掉落身上装备；重新连接不会恢复本局参赛资格。旁观者可通过 `/mace spectate` 选择存活玩家进行跟随观战。

## 装备、补给与强化

开局默认获得下界合金剑、下界合金斧、两把重锤，以及 16 份牛排、32 个木板和 8 个风弹。剑与斧为不可损坏物品；**两把重锤分别具有默认 40 点自定义耐久**。食物、方块、风弹数量及物品位置可在配置中调整。

个人快捷栏布局包含剑、斧、两把独立重锤、食物、方块、风弹七项。编辑菜单通过预览物品交换或拖动位置，完成交换及退出时保存；预览不占用或移动真实背包物品。

战场补给分为 **一星、二星、三星**，通过箱子上方的浮空文字区分。每档使用独立的权重、抽取次数和空抽概率，物品随机放入箱内不同槽位。默认补给包括：

- 食物、木板、风弹、末影珍珠、金苹果与治疗等药水。
- 重锤、盾牌、鞘翅、图腾，以及 1.21.11 的铁长矛和钻石长矛。
- 武器附魔书与拾取后生效的被动附魔书。

**长矛使用 1.21.11 原生 `IRON_SPEAR` / `DIAMOND_SPEAR` 物品和 `LUNGE` 附魔，独立于三叉戟。** 长矛的戳刺、冲锋及突进由该版本原生机制处理，插件接入其补给、强化与耐久。

带自定义耐久的物品会在说明与原版耐久条上显示剩余状态，实际使用扣除耐久。耐久耗尽时物品消失，可按配置触发爆裂；爆裂的强度和是否破坏方块分别配置。

耐久合并通过背包操作完成：拿起一件同类型、带自定义耐久的物品，用鼠标右键点击自己背包中**已损耗且仍有耐久**的目标物品，消耗一件来源物品，并将来源剩余耐久的 **一半向下取整** 加入目标。例如来源剩余 25 点，目标由 20/40 恢复至 32/40。**满耐久目标会拒绝合并，鼠标与背包中的两件原物品均保留。** 来源不足 2 点时也不会合并；成功合并后若剩余耐久超过目标原最大耐久，最大耐久同步提高至合并后的数值。普通地面拾取保留物品本身。

武器附魔书可放在鼠标上，右键点击自己背包中要强化的装备；也可将附魔书与装备分别放在主副手，右键应用。只有兼容且能提高等级的强化才消耗书。支持锋利、密度、破甲、风爆、耐久、经验修补和长矛突进等；等级上限由 `loot.respect-max-level` 与 `loot.absolute-max-level` 控制。

自定义耐久物品的经验修补采用本玩法的击杀修复：确认击杀后，修复携带的对应附魔装备，默认每级恢复其最大耐久的 25%。

三类被动书持续至本局结束或玩家淘汰：

| 被动书 | 作用 |
| --- | --- |
| 战斗本能 | 增加造成的伤害，默认每层 10% |
| 复苏之风 | 增加获得的治疗，默认每层 10% |
| 乘胜追击 | 储存击杀触发次数；击杀敌人时消耗一层，增加伤害与治疗层数，并回复生命 |

被动上限、每层倍率、击杀治疗数值均位于 `loot.yml`，满层时未生效的书保留为物品。

## 菜单、记分板与战绩

玩家界面采用中文文案、白色阴影标题和独立阶段信息。大厅提供玩法入口、队伍、快捷栏布局、个人战绩与观战列表。装饰和按钮由菜单会话保护，布局编辑仅允许操作其预览槽位；分页按钮只在存在对应页时显示。

主菜单仅显示关闭按钮，各子菜单使用返回按钮。服主可将根菜单关闭入口改为返回服务器主菜单：

```yaml
menu:
  close-as-back: true
  back-command: menu
```

记分板按等待、倒计时、降落、交战、结算和旁观切换，显示实际人数、存活阵营、本局击杀、保护期与边界状态；交战时提供至多四名队员的生命或淘汰状态。Tab 页头页尾显示当前阶段与队伍信息，文案在 `scoreboard.yml` 配置。

战绩包括胜场、击杀、阵亡、参与场次、K/D、胜率与单局最高击杀。战绩菜单提供胜场、击杀、K/D、单局最高击杀和场次五种排行榜；同一按钮左键向后切换、右键向前切换，首尾循环。

## 命令

主命令为 `/macesurvival`，别名为 `/mace`、`/ms`。下表统一使用 `/mace`。命令支持按权限过滤的 Tab 补全；`help` 按权限分页显示，帮助行不附加聊天前缀。

| 玩家命令 | 功能 |
| --- | --- |
| `/mace` 或 `/mace menu` | 打开玩法主菜单 |
| `/mace help [页码]` | 查看有权限使用的命令 |
| `/mace stats [玩家名]` | 打开自己的战绩菜单，或查询已记录玩家的战绩 |
| `/mace layout` | 编辑个人开局快捷栏布局 |
| `/mace team` | 打开公开队伍菜单 |
| `/mace team create [队名]` | 创建队伍；不填名称则进入聊天输入 |
| `/mace team join <队伍ID>` | 加入对应公开队伍 |
| `/mace team leave` | 离开当前队伍 |
| `/mace team invite <在线玩家>` | 由队长邀请玩家 |
| `/mace team accept` | 接受当前有效邀请 |
| `/mace team list` | 列出队伍与对应 ID |
| `/mace spectate` | 打开观战目标列表 |
| `/mace leaderboard [wins\|kills\|kd\|streak\|games]` | 显示对应排行榜前十名，默认胜场榜 |

创建队名时菜单关闭，玩家在聊天中输入；输入期间显示屏幕提示、施加黑暗效果并限制移动。输入 `cancel` 或蹲下可取消，超时后恢复操作。

| 管理命令 | 功能 |
| --- | --- |
| `/mace start` | 在人数、阵营条件满足时启动倒计时 |
| `/mace stop` | 中止当前流程并返回大厅，不结算胜利；暂停自动开局，使用 `start` 重新开启 |
| `/mace reload` | 重载配置并补回被删除的默认文件；配置语法错误时显示失败提示 |
| `/mace map info` | 查看竞技场世界、补给点数量与阶段 |
| `/mace map regen` | 在等待阶段预生成或重新生成竞技场 |
| `/mace loot test <1\|2\|3>` | 打开对应星级的随机补给预览 |

## 权限与可选依赖

使用 Bukkit 标准权限，可通过 LuckPerms 分配。玩家权限默认开放，管理员权限默认仅 OP 拥有；普通玩家的帮助与补全不显示其没有权限的管理分支。

| 权限 | 作用 |
| --- | --- |
| `macesurvival.player` | 玩家功能权限集合 |
| `macesurvival.menu` | 玩法菜单 |
| `macesurvival.stats` | 战绩查询 |
| `macesurvival.team` | 队伍功能 |
| `macesurvival.layout` | 快捷栏布局 |
| `macesurvival.spectate` | 观战菜单 |
| `macesurvival.leaderboard` | 排行榜命令 |
| `macesurvival.admin` | 全部管理权限集合 |
| `macesurvival.admin.start` / `.stop` / `.reload` / `.map` / `.loot` | 对应管理分支，例如 `macesurvival.admin.reload` |

可选依赖：

- **PlaceholderAPI**：用于配置文本中的变量与自定义货币余额读取。
- **Vault + 经济实现插件**：接入服务器经济账户，仅安装 Vault 本身不提供账户服务。
- **LuckPerms**：用于管理上述标准权限；插件运行不要求安装 LuckPerms。

经济后端优先级为启用的自定义货币、Vault 经济服务、内置金币。默认每次击杀奖励 10 金币、获胜奖励 50 金币，参与奖励默认关闭，可在 `economy.rewards` 调整。

自定义货币使用配置命令加减余额，使用 PlaceholderAPI 读取余额。命令支持 `{player}`、`{uuid}`、`{amount}`，兼容 `%player_name%`、`%player_uuid%`、`%金币数%` 和 `%amount%`。`economy.custom.id` 是稳定标识，修改显示名称时应保留该值；离线队员的自定义货币奖励持久保存，恢复对应货币后上线补发。

## 记分板与 Tab

侧边栏按场地准备、等待、倒计时、降落、生存对局、结算和旁观身份显示对应数据。比赛中展示本局用时、保护状态、存活人数与阵营数、本局击杀、边界直径和缩圈状态；队伍区域最多显示四名成员的当前生命或淘汰状态。单人玩家各自作为一个阵营计算，榜单中的累计战绩与侧边栏的本局击杀分别取自对应数据。

Tab 页头默认显示玩法名称、当前阶段和玩家人数，页尾显示玩法说明与自己的队伍。玩家名称通过原生记分板队伍显示所属小队的颜色和队伍编号，淘汰玩家使用灰色及 `☠` 标识；单人玩家保留白色名称。

这些内容集中在 `scoreboard.yml` 配置：`lines` 调整各阶段侧边栏，`tab.header` / `tab.footer` 调整 Tab，`nametag` 调整队伍和淘汰前缀，`update-ticks` 默认每 20 tick 刷新。文本支持现有颜色格式与 PlaceholderAPI；关闭记分板会同时清理插件设置的 Tab 页头页尾。该玩法服由插件管理玩家记分板，安装其他侧边栏或名称队伍插件时，需要统一显示职责以避免互相覆盖。

## PlaceholderAPI 变量

安装 PlaceholderAPI 后，插件启动时自动注册 `macesurvival` 扩展，无需另行下载扩展包。以下是当前实际提供的变量，可用于支持 PlaceholderAPI 的菜单、聊天和显示插件；本插件带玩家上下文的可配置文本同样可以读取这些变量。

| 变量 | 返回内容 |
| --- | --- |
| `%macesurvival_state%` | 原始阶段名称：`BOOTING`、`WAITING`、`COUNTDOWN`、`DROPPING`、`RUNNING`、`ENDING` |
| `%macesurvival_phase%` | `scoreboard.yml` 配置的当前阶段显示名称 |
| `%macesurvival_players%` | 当前在线且仍为存活参赛身份的玩家人数，等待阶段为参赛人数 |
| `%macesurvival_alive%` | 本局仍存活且在线的参赛玩家人数 |
| `%macesurvival_teams%` | 本局仍存活的阵营数；单人玩家各自计为一个阵营 |
| `%macesurvival_countdown%` | 开局倒计时数值，单位为秒 |
| `%macesurvival_elapsed%` | 本局已进行的秒数，返回整数 |
| `%macesurvival_kills%` | 玩家累计击杀数 |
| `%macesurvival_deaths%` | 玩家累计阵亡数 |
| `%macesurvival_wins%` | 玩家累计胜场数 |
| `%macesurvival_games%` | 玩家累计参赛场次 |
| `%macesurvival_kd%` | 玩家累计击杀阵亡比，保留两位小数 |
| `%macesurvival_round_kills%` | 在线玩家本局击杀数 |
| `%macesurvival_squad%` | 在线玩家当前队名；未组队时返回 `单人生存` |
| `%macesurvival_role%` | 在线玩家当前身份：`参赛者` 或 `旁观者` |
| `%macesurvival_balance%` | 在线玩家当前经济后端的格式化余额 |

全局阶段与人数变量不依赖玩家上下文；累计战绩变量需要玩家身份，并可读取已保存的离线战绩。最后四项需要玩家在线，离线时返回空文本。`%macesurvival_elapsed%` 是整数秒，侧边栏内置的 `{elapsed}` 则按 `分:秒` 显示；`{team_1}` 至 `{team_4}` 等侧边栏内部替换项不属于 PlaceholderAPI 变量。

## 配置和持久化文件

所有可编辑默认配置均随 JAR 放在 `src/main/resources` 中，运行时位于 `plugins/MaceSurvival/`：

| 文件 | 内容 |
| --- | --- |
| `config.yml` | 大厅、参赛人数、组队、降落、地图、边界、初始装备、导航与经济 |
| `loot.yml` | 各星级权重表、抽取次数、药水、附魔、耐久、击杀修复与被动书 |
| `messages.yml` | 聊天、标题、输入提示、帮助及可配置聊天前缀 |
| `scoreboard.yml` | 分阶段侧边栏、队员状态与 Tab 页头页尾 |
| `menu/main.yml` | 大厅主菜单、快捷栏入口、根菜单返回样式 |
| `menu/team.yml` | 公开队伍、创建、离队、分页与空状态 |
| `menu/layout.yml` | 个人快捷栏编辑和保存反馈 |
| `menu/stats.yml` | 个人战绩及五类排行榜 |
| `menu/spectate.yml` | 存活玩家观战列表及分页 |
| `layouts.yml` | 玩家 UUID 对应的个人装备位置 |
| `stats.yml` | 跨局保留的累计战绩 |
| `balances.yml` | 内置金币余额与待补发的自定义货币奖励 |

文本支持 `&`、`§` 颜色、十六进制颜色、MiniMessage 及 Adventure JSON。聊天框消息统一不附加插件前缀（`messages.yml` 的 `prefix` 键仅为旧配置兼容保留）；菜单物品名称、说明、槽位与声音可分别配置。

`config_version` 用于配置结构升级，与插件版本号分别维护。重载会补齐缺失文件和字段，兼容旧奖励键、队伍大小等设置；旧菜单采用结构迁移并保留 `.v1.bak` 原件。v2 默认菜单说明和等待侧边栏会升级为按参赛规则与阶段变化的模板，仅替换仍与旧默认完全一致的字段，服主已自定义的内容继续沿用。不要将备份当作当前生效的菜单文件。

世界名称前缀、半径、种子、建筑和补给数量在 `arena` / `chest` 配置。固定地图种子使用 `arena.seed-mode: fixed`；默认 `random` 每次生成使用新种子。竞技场属于每局临时世界，大厅单独保留。

`game.max-players` 默认配置为 64，它是服主可调整的参赛上限，不代表已经完成 64 名真人同时在线的性能验证；应结合机器资源、其他插件与实际压测确定容量。

## 构建与安装

1. 安装 JDK 21，并将 `JAVA_HOME` 指向 JDK 目录。
2. 在项目根目录执行 `mvn clean package`；Windows 也可使用仓库中的 `mvnw.cmd clean package`。
3. 构建产物为 `target/MaceSurvival-1.0.0.jar`，具体文件名跟随 `pom.xml` 的版本。
4. 将构建后的插件 JAR 放入目标 **Paper 1.21.11** 玩法服的 `plugins/`，按需安装可选依赖。
5. 首次启动生成默认配置；配置大厅位置、玩法参数与经济后，使用 `/mace reload` 重载受支持的运行配置。世界名等影响世界创建的设置应在对应世界创建前配置。

插件在自己的临时竞技场内生成地图，完成一局后清理该竞技场，不复制预置世界。不要把临时竞技场世界作为长期建筑或生存存档使用。

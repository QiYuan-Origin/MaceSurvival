# MaceSurvival

A single-server Mace Battle Royale game mode for Paper 1.21.11.

Join the server and you are already in the waiting lobby. Join mid-round and you
drop straight into spectator mode. The arena is generated by the plugin at
runtime, so there is nothing for an administrator to build and no world to copy.

## Highlights

- **Single-server flow.** Waiting lobby, countdown, grace period, live round and
  end screen are one state machine. The round can restart the server when it
  ends so every match starts from a clean map.
- **Generated arena.** Structures, loot chests and star-rated chest holograms are
  placed procedurally inside a configurable radius. No schematics required.
- **Skydive opening.** Players fade to black, are lifted to the drop height and
  fall with real momentum. Horizontal steering stays responsive while the
  vertical look angle is locked, and the parachute opens automatically near the
  ground.
- **Mace-first loadout.** Every player starts with a mace, food, blocks and wind
  charges. Hotbar positions are configurable server-side and each player can
  reorder their own slots from the layout menu.
- **Durability loot.** Loot is expressed as durability rather than raw gear.
  Picking up a duplicate merges its durability into the item you already carry,
  and an overloaded mace detonates.
- **Enchantment books.** Books can apply on pickup or on right-click against a
  held weapon, with optional level caps beyond vanilla limits.
- **Squads.** Four players per squad by default, with invites from chat, from the
  command line or from the team menu.

## Requirements

| | |
|---|---|
| Server | Paper 1.21.11 or newer |
| Java | 21 |
| Optional | PlaceholderAPI, Vault, LuckPerms |

All three optional dependencies are soft. Without Vault the plugin falls back to
its own internal balance store; without PlaceholderAPI the placeholder-driven
strings simply render as written.

## Building

```bash
mvn clean package
```

The shaded jar lands in `target/MaceSurvival-<version>.jar`. Drop it into
`plugins/` and restart the server.

## Commands

The main command is `/macesurvival`, aliased to `/mace` and `/ms`. Every branch
has tab completion, and administrative branches are hidden from players who lack
the matching permission.

### Players

| Command | Description |
|---|---|
| `/mace` | Open the main menu |
| `/mace help` | List the commands available to you |
| `/mace menu` | Open the main menu |
| `/mace stats [player]` | Open your stats menu, or print another player's record |
| `/mace team` | Open the squad menu |
| `/mace team create` | Start a fresh squad |
| `/mace team invite <player>` | Invite a player to your squad |
| `/mace team accept <leader>` | Accept an invitation |
| `/mace team leave` | Leave your current squad |
| `/mace spectate` | Open the spectator target list |

### Administrators

| Command | Permission | Description |
|---|---|---|
| `/mace start` | `macesurvival.admin.start` | Force-start the round |
| `/mace stop` | `macesurvival.admin.stop` | Force-stop the round |
| `/mace reload` | `macesurvival.admin.reload` | Reload configuration |
| `/mace map regen` | `macesurvival.admin.map` | Regenerate the arena |
| `/mace map info` | `macesurvival.admin.map` | Report structure and chest counts |
| `/mace loot test <stars>` | `macesurvival.admin.loot` | Preview a loot roll |

`/mace reload` also repairs the configuration directory: any managed file that
has been deleted is restored from the jar, and the restored file names are
reported back to you. New configuration keys added by a plugin update are merged
in as defaults, so you never need to delete a file to pick them up.

## Permissions

| Node | Default | Description |
|---|---|---|
| `macesurvival.play` | everyone | Join and play |
| `macesurvival.menu` | everyone | Open the menus |
| `macesurvival.team` | everyone | Create and manage a squad |
| `macesurvival.stats` | everyone | View stats |
| `macesurvival.admin` | operators | Parent of every administrative node |
| `macesurvival.admin.reload` | operators | Reload configuration |
| `macesurvival.admin.start` | operators | Force-start a round |
| `macesurvival.admin.stop` | operators | Force-stop a round |
| `macesurvival.admin.map` | operators | Regenerate or inspect the arena |
| `macesurvival.admin.loot` | operators | Inspect and test loot tables |
| `macesurvival.admin.spectate` | operators | Free spectator movement |

LuckPerms is supported through the standard Bukkit permission API, so these
nodes can be granted to groups or tracks without any extra configuration.

## Configuration

Everything ships inside the jar and is written to disk on first start.

```
plugins/MaceSurvival/
├── config.yml        game rules, drop, arena, loadout, loot, economy, menus
├── messages.yml      every player-facing string
├── loot.yml          loot tables by star rating
├── layouts.yml       per-player hotbar preferences (written by the plugin)
├── stats.yml         win, kill, death and match counters
└── menu/
    ├── main.yml
    ├── team.yml
    ├── layout.yml
    ├── stats.yml
    └── spectate.yml
```

### Notable keys

| Key | Default | Description |
|---|---|---|
| `game.min-players` | `2` | Players required before the countdown starts |
| `game.max-players` | `40` | Lobby capacity |
| `game.squad-size` | `4` | Players per squad |
| `game.lobby-countdown` | `60` | Countdown in seconds |
| `game.grace-period` | `20` | Seconds of protection after landing |
| `game.time-limit` | `1800` | Round length before a forced finish |
| `game.restart-on-end` | `true` | Restart the server after the end screen |
| `drop.height` | `320` | Skydive start height |
| `drop.fall-speed` | `1.6` | Free-fall speed in blocks per tick |
| `drop.open-at-height` | `14` | Height at which the parachute opens |
| `arena.radius` | `400` | Arena radius in blocks |
| `arena.structures` | `26` | Structures placed per generation |
| `loot.merge-durability` | `true` | Merge duplicate loot into carried gear |
| `loot.durability-explosion` | `true` | Detonate an overloaded mace |
| `loot.absolute-max-level` | `10` | Enchantment ceiling when vanilla caps are ignored |
| `menu.close-as-back` | `false` | Render the close button as a back button |
| `menu.back-command` | `menu` | Command run by the back button |

### Linking back to a server hub

The last slot of the main menu is either a close button or a back button, never
both. Set `menu.close-as-back` to `true` and point `menu.back-command` at your
hub command to wire the plugin's main menu into an existing server menu:

```yaml
menu:
  close-as-back: true
  back-command: menu
```

The command is dispatched as the player, so it honours that player's own
permissions.

### Custom currency

Rewards go through Vault when it is present. If your economy is command-driven
instead, describe it in `config.yml` and the plugin will call your commands:

```yaml
economy:
  custom:
    enabled: true
    name: 'Coins'
    take-command: 'eco take {player} {amount}'
    give-command: 'eco give {player} {amount}'
    balance-placeholder: '%vault_eco_balance%'
```

`{player}`, `{uuid}` and `{amount}` are substituted before dispatch.

## Text formatting

Every configurable string accepts hex tags (`<#C9A227>`), gradients, drop
shadows (`<shadow:#404040:1>`) and legacy `&` or `§` colour codes in the same
value. Messages are rendered through Adventure, so the shadowed style used by the
default configuration survives on modern clients while remaining readable on
older ones.
